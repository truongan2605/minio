# HTTP API

The service exposes three surfaces:

- **S3** — everything not matched by an explicit route. Authenticated with AWS
  Signature V4 and proxied to storage.
- **Admin** — JSON endpoints that manage MinIO IAM users and bucket policies.
- **Operational** — health, readiness and the routing table.

---

## S3 surface

Any path that does not match an endpoint below is treated as an S3 request.
Path-style addressing is assumed: `/{bucket}/{key}`.

### Authentication

Requests may be anonymous or signed.

**Anonymous** requests (no `Authorization` header) are forwarded unsigned. They
serve public objects and pre-signed URLs. A request for a bucket with no route
returns 404.

**Signed** requests must carry a SigV4 header:

```
Authorization: AWS4-HMAC-SHA256 Credential={access-key}/{yyyymmdd}/{region}/s3/aws4_request,
               SignedHeaders=host;x-amz-content-sha256;x-amz-date,
               Signature={hex}
X-Amz-Date: 20260819T101530Z
X-Amz-Content-Sha256: {hex sha256 of the body}
```

Validation, in order:

| Check | Failure |
| --- | --- |
| Header parses as SigV4 | 400 if not SigV4 at all, 403 if malformed |
| `SignedHeaders` covers `host`, `x-amz-date`, `x-amz-content-sha256` | 403 |
| `X-Amz-Date` within `--signature-max-skew` of now | 403 |
| Access key known to the control plane | 403 (unknown) / 503 (control plane down) |
| Recomputed signature matches | 403 |
| `X-Amz-Date` and `X-Amz-Content-Sha256` match what was signed | 403 |

The client's signature is never forwarded. The proxy re-signs with the
credentials the storage zone expects.

### Streaming uploads

A client may stream an upload rather than hashing it up front, signalled by an
`X-Amz-Content-Sha256` of `STREAMING-AWS4-HMAC-SHA256-PAYLOAD`,
`STREAMING-AWS4-HMAC-SHA256-PAYLOAD-TRAILER` or
`STREAMING-UNSIGNED-PAYLOAD-TRAILER`, with the body framed in `aws-chunked`
encoding.

The proxy decodes the framing and re-signs the decoded bytes, so the object
stored is the real content. For the signed variants every chunk signature is
verified; a tampered payload fails the upload with 403 and never reaches
storage. `Content-Encoding: aws-chunked`, `X-Amz-Decoded-Content-Length` and
`X-Amz-Trailer` are dropped from the forwarded request, since they no longer
describe what is being sent.

This is transparent: no client configuration is needed.

### Supported operations

| Operation | Path | Handling |
| --- | --- | --- |
| ListBuckets | `GET /` | Fanned out to every zone, union of bucket names |
| ListObjectsV2 | `GET /{bucket}/` | Merged across zones, or served from the MySQL index |
| GetObject | `GET /{bucket}/{key}` | Download endpoint if configured, otherwise proxied |
| PutObject | `PUT /{bucket}/{key}` | Proxied; the body is replayable across zone fallback |
| Everything else | any | Proxied verbatim to the zones in order |

### Listing behaviour

A `GET` on a bucket root is a listing. Which path serves it:

| Condition | Path |
| --- | --- |
| `?location` present | Plain proxy — this is a bucket sub-resource, not a listing |
| Bucket starts with `probe-bucket-sign-` | Plain proxy — an SDK region probe |
| Route has `useSQLIndex` and no `delimiter` | MySQL index |
| Otherwise | Multi-zone fan-out and merge |

**Continuation tokens are opaque.** Echo back whatever `NextContinuationToken`
you were given; do not parse or construct one. Their internal format differs
between the index path and the fan-out path, and it has changed in this
release — tokens issued by the previous build are still accepted.

**Known deviation.** A merged listing may return more objects than `MaxKeys`,
because the zones cannot be asked to rewind a page. Clients that paginate by
following `NextContinuationToken` are unaffected; clients that assume exactly
`MaxKeys` entries per page will see more. See
[optimization-proposal.md](optimization-proposal.md) for the fix.

## Admin surface

All admin endpoints accept and return `application/json`.

Responses share an envelope:

```json
{ "success": true, "data": { … } }
{ "success": false, "error": "human readable reason" }
```

### `POST /v1/policy`

Applies one key pair's access across every zone hosting the listed buckets. The
zones are discovered from the routing table, so the caller does not need to know
the topology.

```json
{
  "buckets": [
    { "name": "media",   "is_public_read": true  },
    { "name": "backups", "is_public_read": false }
  ],
  "keypair": {
    "attributes": { "accessKey": "AK…", "secretKey": "…" }
  },
  "force": false
}
```

For every zone involved it creates the IAM user, attaches a read-write canned
policy scoped to those buckets, and sets each bucket's anonymous-read policy.
The key pair's cache entry is invalidated so the change takes effect at once.

| Status | Meaning |
| --- | --- |
| 200 | `{"success":true,"data":{"zones":N}}` |
| 400 | Missing key pair, empty bucket list, unroutable bucket, or a zone with no admin credentials |
| 500 | A zone rejected the operation |

> `force` is accepted for compatibility and currently has no effect.

### `POST /v2/keypair`

Creates or updates an IAM user on one specific endpoint. Idempotent: an existing
policy of the same name is replaced, so a downgrade actually takes effect.

```json
{
  "end_point":    "https://zone-a.internal",
  "admin_key":    "…",
  "admin_secret": "…",
  "access_key":   "AK…",
  "secret_key":   "…",
  "buckets":      ["media", "backups"],
  "policy":       "rw",
  "readonly":     false,
  "source_ip":    ["203.0.113.0/24"]
}
```

`policy` selects the permission set; `readonly` is the fallback when `policy` is
absent or unrecognised.

| `policy` | Actions granted |
| --- | --- |
| `r` | `s3:GetObject`, `s3:GetBucketLocation`, `s3:ListBucket` |
| `w` | `s3:PutObject` only — upload without read-back |
| `rw` | `s3:*` on the listed buckets |
| absent, `readonly: true` | same as `r` |
| absent, `readonly: false` | same as `rw` |

`source_ip`, when present, restricts the key to those CIDRs.

| Status | Meaning |
| --- | --- |
| 200 | `{"success":true,"data":{"mode":"rw"}}` |
| 400 | Malformed body, or `admin_key`/`admin_secret` missing |
| 500 | MinIO rejected the operation |

### `POST /v2/getBucketPolicy`

Reads a bucket's anonymous-access configuration.

```json
{
  "end_point": "https://zone-a.internal",
  "admin_key": "…", "admin_secret": "…",
  "bucket_name": "media"
}
```

Response — admin credentials are never echoed back:

```json
{
  "end_point": "https://zone-a.internal",
  "bucket_name": "media",
  "is_public_read": true,
  "ips": ["203.0.113.0/24"],
  "ignores": ["private/secret.pdf"]
}
```

| Status | Meaning |
| --- | --- |
| 200 | Policy read and summarised |
| 400 | Malformed body or missing admin credentials |
| 409 | The bucket carries a policy this service did not write and cannot summarise |
| 500 | MinIO rejected the read |

Only the four shapes this service produces are recognised: private, private with
public exceptions, public, and public with private exceptions.

### `POST /v2/setBucketPolicy`

Installs a bucket's anonymous-access configuration. Same body as
`getBucketPolicy` plus `is_public_read`, `ips` and `ignores`.

| `is_public_read` | `ignores` | Resulting policy |
| --- | --- | --- |
| `false` | empty | Deny anonymous `GetObject` on the whole bucket |
| `false` | set | Allow anonymous `GetObject` on exactly those keys, nothing else |
| `true` | empty | Allow anonymous `GetObject` on the whole bucket |
| `true` | set | Allow the bucket, then Deny those specific keys |

`ips`, when set, adds a source-IP condition to the Allow statement.

### `GET /v2/files`

Internal listing backed by the MySQL index. **Not mounted at all** unless
`--files-api-token` is configured.

```
GET /v2/files?bucket=media&prefix=reports/&limit=50&offset=0
Authentication: Bearer {files-api-token}
```

| Parameter | Default | Notes |
| --- | --- | --- |
| `bucket` | — | Required |
| `prefix` | `""` | LIKE metacharacters (`%`, `_`, `\`) are escaped |
| `limit` | 10 | Capped at `--index-default-max-keys` |
| `offset` | 0 | |

```json
{
  "success": true,
  "data": { "files": ["reports/a.pdf", "reports/b.pdf"], "next": 50 }
}
```

Note the header is `Authentication`, not `Authorization` — this is historical
and preserved for compatibility.

| Status | Meaning |
| --- | --- |
| 200 | Page returned |
| 400 | `bucket` missing |
| 403 | Bad or missing token |
| 500 | Index query failed |

## Operational surface

### `GET /healthz`

Liveness. Answers 200 as long as the process is running. Use it as the restart
probe.

### `GET /readyz`

Readiness. Fails while the service cannot serve traffic, so an orchestrator or
load balancer keeps it out of rotation.

```json
{ "status": "ready", "routes": 42, "routes_updated": "2026-08-19T10:15:30Z", "cached_keys": 118 }
```

```json
{ "status": "unready", "problems": { "mysql": "dial tcp …: connect: connection refused" } }
```

| Status | Meaning |
| --- | --- |
| 200 | Routing table populated and MySQL reachable |
| 503 | Empty routing table or unreachable database |

### `GET /ping`

Returns the current routing table as JSON, keyed by bucket pattern. Useful for
confirming what the service believes about a bucket.

> `/ping` exposes the internal topology, including zone hostnames. Keep it off
> the public listener; see [operations.md](operations.md).

### `PUT /update`

Forces an immediate routing-table refresh and returns the new table. Use it
after changing `bucket-locations` in the control plane instead of waiting for
the next tick.

| Status | Meaning |
| --- | --- |
| 200 | Refreshed; body is the new table |
| 500 | The refresh failed; the previous table is still serving |
